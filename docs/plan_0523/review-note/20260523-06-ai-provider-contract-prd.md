# PRD: Correct V0 AI Provider Contract And Documentation

> *This was generated by AI from the V4 provider-contract review context.*

## Problem Statement

V4 currently conflates three different concepts in the model layer: Ark as the paid primary provider entry point, Seedance as the video model capability/name, and the OpenAI-compatible fallback LLM configured under `OPENAI_BASE_URL`.

From the team's perspective, this creates two practical risks:

- The system can call the wrong paid API or require a key that does not exist in the real local configuration.
- Active documentation can lead future agents and final-report writers toward obsolete `SEEDANCE_*` configuration, even though the real provider contract uses Ark credentials and endpoints.

The real V0 contract should be easy to read from the active docs, easy to validate in tests, and impossible to confuse with historical planning artifacts.

## Solution

Correct the V0 provider contract so that paid provider fields match the real `.env` API/key shape:

- Keep `MODEL_MODE`.
- Use Ark credentials as the primary text and video provider entry points.
- Use the OpenAI-compatible configuration only as a narrow fallback LLM for 创作蓝图 text generation when Ark text auth/config is unavailable.
- Do not require `SEEDANCE_API_URL`, `SEEDANCE_API_KEY`, or `SEEDANCE_MODEL` in active code, active examples, smoke checks, or current docs.
- Keep `Seedance` as the video model capability/name in architecture language, while making the credential boundary explicitly Ark-based.
- Treat docs correction as part of the feature: archive or demote obsolete active docs, then write a current provider-contract correction document that records what was wrong and what replaced it.

## Implementation Decisions

- Introduce or consolidate a deep model-runtime contract module that resolves provider configuration from environment variables and exposes small, testable outcomes such as selected text provider, selected video provider, and fallback eligibility.
- Keep `MODEL_MODE` with two practical meanings:
  - `real`: missing Ark text or Ark video configuration fails readiness checks loudly.
  - any non-real value, including `mock`: deterministic local fallbacks are allowed.
- Define primary text generation as Ark credentials plus the Ark text endpoint.
- Define primary video generation as Ark credentials plus the Ark video endpoint.
- Define fallback LLM as OpenAI-compatible base URL, API key, and model, used only for 创作蓝图 text generation after Ark text auth/config failure.
- Do not use fallback LLM for video generation.
- Do not switch from Ark text to fallback LLM because of invalid JSON, prompt quality, or schema validation failure. Repair should use the same selected text provider; if repair fails, return deterministic fallback blueprint.
- Preserve the externally meaningful video capability label `Seedance` where useful for product language, provider traces, and 成片 metadata, but do not make `Seedance` a separate credential namespace in active V0.
- Keep `GEMINI_API_KEY` out of the V0 provider contract.
- Remove obsolete `SEEDANCE_*` requirements from active examples, smoke instructions, current support docs, and provider tests.
- Update the real-provider smoke command so it validates Ark text and Ark video requirements.
- Update active architecture docs to describe Ark as the paid provider boundary and OpenAI-compatible runtime as fallback LLM only.
- Archive or clearly demote historical docs that still describe standalone `SEEDANCE_*` API keys as active truth.
- Add a new current provider-contract correction document that summarizes:
  - the historical wrong assumption;
  - the corrected Ark text/video contract;
  - the narrow fallback LLM trigger;
  - the reason docs were archived or rewritten.
- Keep historical review/grill notes available for audit, but do not let them appear as current setup instructions.

## Testing Decisions

- Good tests should assert externally observable behavior: selected provider, fallback eligibility, errors in real mode, payload shape, metadata, and docs references. They should not assert private helper implementation details.
- Unit test the model-runtime contract with synthetic environment maps rather than process-global mutation where practical.
- Unit test creative blueprint generation with stubbed text calls:
  - Ark is selected before fallback LLM when both are configured.
  - fallback LLM is selected only when Ark text config/auth is unavailable.
  - invalid JSON triggers same-provider repair.
  - unrepaired invalid output returns deterministic fallback blueprint.
- Unit test video generation with stubbed network calls:
  - Ark video config is sufficient.
  - obsolete `SEEDANCE_*` config is not required.
  - real mode fails loudly without Ark video config.
  - mock mode can still return the fallback video.
- Update server tests that currently configure standalone Seedance variables so they use the corrected Ark video contract.
- Update demo-readiness/docs tests so they read current support docs and assert the corrected provider vocabulary.
- Keep real network smoke checks opt-in and operator-run; do not require paid model calls in normal unit tests.

## Out of Scope

- Adding Gemini support to V0.
- Adding a new model SDK solely for this correction.
- Changing the V0 two-step flow, 创作蓝图 schema, 分镜 semantics, or 成片任务 lifecycle.
- Adding raw prompt editing to the UI.
- Adding text-to-video as a primary V0 path.
- Running paid provider smoke tests on every PR by default.
- Publishing real secrets or endpoint values in docs.
- Rewriting all archived historical notes; only active docs need to be corrected or superseded.

## Further Notes

This PRD follows the provider-contract review note created on 2026-05-23. The core correction is:

```text
Primary text model: ARK_API_KEY + ARK_TEXT_ENDPOINT_ID
Primary video model: ARK_API_KEY + ARK_VIDEO_ENDPOINT_ID
Fallback LLM: OPENAI_BASE_URL + OPENAI_API_KEY + OPENAI_MODEL
```

Fallback LLM is only for text/creative-blueprint recovery when Ark text auth or configuration is unavailable. It should not participate in video generation.
