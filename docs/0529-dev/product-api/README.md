# Product API 文档

本目录给产品经理使用。目标不是讲清所有字段，而是说明接口支撑哪些产品能力、用户旅程如何推进、成功和失败时用户会看到什么。

你可以从这里开始写产品文档：先写用户动作和业务目标，再补接口路径。不要一开始就陷入 schema 细节。

## 文件说明

| 文件 | 用途 |
|---|---|
| `user-journey.md` | 用户从创建项目到生成最终视频的完整旅程 |
| `capability-map.md` | 用户动作、系统能力、关键接口和当前状态 |
| `status-and-copy.md` | 状态含义、按钮文案、错误提示建议 |
| `risks-and-gaps.md` | 当前产品缺口、风险、待确认问题 |

## 推荐写法

每个能力尽量用同一张业务卡片描述：

```md
## 能力名称

业务目的：
用户在什么场景下需要这个能力。

触发时机：
用户点击什么、页面加载什么、系统自动做什么。

成功结果：
系统状态如何变化，用户看到什么。

失败情况：
哪些失败用户能理解，前端应该怎么提示。

关键接口：
只列 endpoint，不展开字段 schema。
```

## 产品文档不建议放的内容

- Zod schema 完整定义。
- 数据库表字段。
- provider 原始请求体。
- TypeScript 类型细节。
- 自动化测试细节。
