# 2026-05-23 Grill Note：V0 只读剧本预览与结构化创作参数

## 审阅状态

已确认。

## 背景

V0 已确认采用两步式主流程：先生成剧本/基础分镜，再点击一键成片。这里需要明确用户在确认阶段能修改什么，避免“Prompt 调整”演变成直接编辑图生视频 prompt。

## 已确认决策：V0 剧本/基础分镜预览只读

V0 的确认页只读展示：

- 剧本叙事。
- 视觉风格。
- 2-4 个基础分镜。
- 每个分镜的画面描述、镜头运动、口播/字幕文案。

用户不在 V0 内联编辑：

- 剧本文案。
- shot 内容。
- shot 时长。
- shot 排序。
- 图生视频 prompt。

## 用户允许修改的内容

用户允许修改的内容通过 UI 的确定字段传入：

```text
商品标题
核心卖点
目标人群
风格偏好
商品主图/上传素材
```

如果用户不满意剧本/基础分镜，应返回表单修改这些结构化字段，然后重新生成剧本。

## 设计口径

V0 不暴露 raw video prompt。`packages/ai` 内部根据结构化字段、Script、StoryboardShot 和保守三段式模板构造 Seedance prompt。

这样保留了 PRD 中“Prompt 调整”的用户价值，但把它收敛成可控的创作参数，而不是让商家直接触碰模型底层 prompt。

## 已确认决策：后端拆成两个命令/API

已确认：

```text
拆成两个命令：
1. 生成创作蓝图：返回 Script / StoryboardShot / improvementHints。
2. 一键成片：接收 scriptId，进入 media_generating 并生成 final video。
```

## 下一轮需要继续确认的问题

下一个问题建议讨论：

```text
创作蓝图生成是同步返回，
还是也做异步任务进度？
```

推荐答案：

```text
V0 创作蓝图生成同步返回，UI 显示普通 loading；
只有一键成片进入异步成片任务和进度轮询。
```

原因：

- Ark 文本生成比视频生成短，没必要引入第二套任务状态机。
- V0 的“任务进度”主要服务视频生成长任务。
- 同步蓝图命令能显著降低 API、状态管理和恢复逻辑复杂度。
