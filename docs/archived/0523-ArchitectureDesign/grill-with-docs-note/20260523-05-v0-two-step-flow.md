# 2026-05-23 Grill Note：V0 两步式主流程

## 审阅状态

已确认。

## 背景

V0 范围已经固定为商品素材上传、剧本生成、基础分镜、一键成片、任务进度、预览导出。这里需要明确“一键成片”不是把整个系统做成黑盒，而是在剧本/基础分镜可见之后，把确认后的脚本生成成片。

## 已确认决策：V0 采用两步式主流程

V0 主流程：

```text
上传素材与商品信息
  -> 生成剧本/基础分镜
  -> 用户预览
  -> 点击一键成片
  -> 任务进度
  -> 预览导出
```

Demo 商品可以额外提供快捷路径，但主流程必须让剧本和基础分镜在成片前可见。

## 术语口径

`一键成片` 在 V0 中指：

```text
从已生成的剧本/基础分镜，一次触发 Seedance 生成最终成片。
```

它不指：

```text
从素材上传到最终视频的全流程黑盒一键到底。
```

## 已确认决策：剧本/基础分镜只读确认

V0 的剧本/基础分镜预览采用只读确认：

```text
用户可以返回修改商品标题、卖点、目标人群、风格偏好等结构化字段，
然后重新生成剧本/基础分镜。
用户不直接编辑剧本文案、shot、时长、排序，也不直接触碰图生视频 prompt。
```

这样能保留“Prompt 调整”的产品含义，但把它收敛为确定字段，而不是把底层 video prompt 暴露给商家。

## 已确认决策：后端拆成两个命令/API

已确认：

```text
两步式流程在后端拆成两个命令/API。
创作蓝图生成返回 Script / StoryboardShot / improvementHints。
一键成片接收 scriptId，创建成片任务 GenerationJob。
```

## 下一轮需要继续确认的问题

下一个问题建议讨论：

```text
创作蓝图生成是同步返回，
还是也做异步任务进度？
```

推荐答案：

```text
V0 创作蓝图生成同步返回，UI 显示普通 loading；
只有一键成片进入异步成片任务和进度轮询。
```

原因：

- Ark 文本生成比视频生成短，没必要引入第二套任务状态机。
- V0 的“任务进度”主要服务视频生成长任务。
- 同步蓝图命令能显著降低 API、状态管理和恢复逻辑复杂度。
