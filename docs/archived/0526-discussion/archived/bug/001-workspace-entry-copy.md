# Bug 001: 工作目录入口表述混杂

## 用户反馈

前端工作目录入口的表述混杂，用户难以理解“工作目录入口”和“工作目录名称”的区别。

## 当前代码事实

- `workspacePath` 表示打开一个已有本地目录的路径，来源包括系统目录选择器或手动输入路径。
- `workspaceName` 表示新建一个 Fastify 托管工作目录时的名称 seed。
- 两者在 UI 中并列出现：左侧是“工作目录入口 / 选择目录 / 手动输入路径”，右侧是“工作目录名称 / 新建”。

## 问题判断

这不是单纯文案问题，而是两个不同任务被放在同一层级：

- 打开已有目录：用户已经有一个本地项目目录，希望系统围绕该目录初始化/恢复 workspace。
- 新建目录：用户没有现成目录，希望系统在默认 workspace root 下创建一个新项目目录。

“工作目录名称”容易被理解为当前已选工作目录的名称，但实际只服务于“新建目录”。它不应该作为与“工作目录入口”并列的独立字段。

## 推荐修复方向

将入口区拆成两个明确动作：

1. 主路径：打开已有工作目录
   - label: `打开工作目录`
   - controls: 当前路径只读展示 + `选择目录` + `手动输入路径`
   - result: 调用 `/api/workspaces/init`，恢复或创建 workspace 记录。

2. 次路径：新建工作目录
   - label: `新建工作目录`
   - controls: `目录名` + `新建`
   - help/copy: 说明会在服务端默认 workspace root 下创建目录。

## 待确认问题

V1 首屏是否应该把“打开已有工作目录”作为唯一主入口，把“新建工作目录”降级为 secondary/折叠动作？

推荐答案：是。V1 的产品模型是“基于一个工作目录进行开发”，所以主入口应是打开/恢复本地目录；新建只是没有现成目录时的辅助入口。
